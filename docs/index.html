A runnable version of the 25-case eval set from my appointment agent spec. The agent books and reschedules pickup and delivery appointments for a freight brokerage, and it only writes to the TMS without a coordinator's review once it passes the gate below.

Which case catches each check

An eval set that still passes with a check switched off is not testing that check. Each row is the reference agent with one check off; an outlined or ink square is a case that caught it. Select a row to load it into the switches above.

Seven of the twelve checks are each caught by a single case, the thinnest coverage and the first place to add cases built from a broker's own loads. Two checks can be switched off and the gate still passes. With the portal fallback off, the agent hands the request to a coordinator: a safe, low-severity miss and exactly what the one allowed miss is for. With the first-come, first-served check off, the agent books an appointment the receiver does not need: wasted work rather than a wrong write. Neither is critical, but a second case for each would stop either from slipping through.

What 25 of 25 means

The reference agent reads structured facts, not raw email, so its 25 of 25 shows the spec's rules can be written as code and the grader agrees with a correct policy. It is not a claim about a model.

Every one of the 4,096 combinations of the 12 checks was run through the same grader as the code on GitHub, three runs per case, and a case passes only if it passes every run. The switches above read those precomputed results.
