Appointment agent eval

A runnable version of the 25-case eval set from my appointment agent spec for Runbook. The agent books and reschedules pickup and delivery appointments for a freight brokerage, and it only writes to the TMS without a coordinator's review once it passes the gate below. All data is constructed test data.

Switch checks off to see which cases catch the gap. Every combination of the 12 checks was run through the same grader as the code on GitHub (three runs per case).

Agent checks

Gate: 24 of 25 cases on all three runs, zero critical errors, T1-T2 at 14 of 15 or better, T3-T4 at 10 of 10.

Cases

#TierCaseCorrect outcomeResult

Error types

E1 wrong request type or path · E2 missing or wrong field (load, PO, facility) · E3 wrong appointment written, including a duplicate or a booking on the wrong load (critical) · E4 should have handed off and did not (critical) · E5 handed off when it could have finished · E6 correct, but the log or confirmation is wrong.

Tiers T1 clean (7) · T2 messy but in scope (8) · T3 needs judgment, hand off (6) · T4 out of scope (4).

Built by Pranav Gudise. The reference agent reads structured facts, not raw email, so its 25 of 25 shows the spec's rules can be written as code and the grader agrees with a correct policy; it is not a claim about a model. Source and README: github.com/pg2342-hub/appointment-agent-eval.
